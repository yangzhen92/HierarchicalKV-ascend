# 开发资料文档易用性评估

给定文档目录路径（或文件列表），读取所有可发现的 PDF/MD 文档文件，按评分标准逐文件评估（三维度平均加权评分），汇总后输出完整报告。

## 工作流程

### 阶段一：文件发现与读取

#### 1. 确定输入范围

用户输入可以是以下形式之一：
- **目录路径**：扫描该目录及其子目录下所有 `.md` 和 `.pdf` 文件
- **文件列表**：用户直接列出要评估的文件路径
- **混合输入**：目录 + 额外指定文件

#### 2. 发现文档文件

使用 Glob 工具扫描目标目录，匹配模式：- `**/*.md` — Markdown 文档文件
- `**/*.pdf` — PDF 文档文件

排除非文档文件：图片（`.png`、`.jpg`、`.gif`、`.svg` 等）、配置文件（`.gitattributes`、`.gitignore`、`.yaml`、`.toml` 等）、脚本文件（`.py`、`.js`、`.ts` 等）。

#### 3. 读取文件内容

**Markdown 文件（`.md`）：**
- 直接使用 Read 工具读取全文
- 保留 Markdown 格式以便识别标题层级、代码块、链接等结构
- **提取图片引用：** 识别 `![alt文本](图片URL或路径)` 和 `<img>` 标签，记录每张图片的 alt 文本、源路径、所在章节/行号
- **提取超链接：** 识别 `[链接文本](URL)` 和 `<a href>` 标签，记录每个链接的链接文本、目标 URL、所在章节/行号，区分内部链接（锚点/相对路径）和外部链接

**PDF 文件（`.pdf`）：**
- 优先使用 Python `pdfplumber` 或 `PyMuPDF`（fitz）库提取文本
- 备选方案：使用命令行工具 `pdftotext`（需安装 poppler-utils）
- 提取后保留段落结构和章节标题信息
- 若 PDF 为扫描版（图片型），记录为「无法提取文本」，标记跳过
- **提取图片：** 使用 `PyMuPDF`（fitz）提取 PDF 中嵌入的图片，记录每张图片的页码、位置、尺寸；尝试提取图片附近的标题或说明文字作为上下文
- **提取超链接：** 使用 `PyMuPDF` 提取 PDF 中的超链接注释（LINK annotations），记录链接文本、目标 URL、所在页码和位置
- **图片型 PDF 特殊处理：** 若 PDF 为扫描版，将每页作为一张图片处理，记录页码和尺寸信息，标记为「扫描版 PDF — 图片型」

**读取策略：**

**Markdown 文件（`.md`）— 通常有多个，批量并行读取：**
- 将所有 `.md` 文件按大小分为两组：普通文件（≤ 5000 行）和大文件（> 5000 行）
- **普通文件批量并行：** 在同一批次中发出多个 Read 工具调用，同时读取多个文件。每批次建议 5-8 个文件，避免单次响应过大。多批次时，上一批次全部返回后再发起下一批次
- **大文件分段并行：** 对每个大文件，在同一批次中发出多个 Read 调用（各指定不同行范围），并行获取各段后按行号拼接为完整内容
- 读取失败时记录原因，继续处理其余文件

**PDF 文件（`.pdf`）— 通常仅 1 个，直接读取：**
- 通常只有 1 个 PDF 文件，直接使用 Python `pdfplumber` 或 `PyMuPDF`（fitz）一次性提取全文
- 若 PDF 页数较多（> 50 页），可按章节/页码分段提取，每段记录摘要
- 读取失败时记录原因，继续处理其余文件

**上下文溢出保护 — 流式处理模式：**

当 MD 文件数量较多（> 10 个）或单个文件较大，可能导致所有文件内容超出上下文窗口时，自动切换为**流式处理模式**。此模式下不将所有文件一次性读入上下文，而是逐文件完成「读取 → 预处理 → 分类 → 三维度评估」全流程。

**跨文件关联感知：**

文档文件之间可能存在以下关联关系，流式处理时不能丢失：

| 关联类型 | 示例 | 影响 |
|----------|------|------|
| 交叉引用 | 文件 A 中 `[详见 API 文档](api.md)` | 需验证链接目标是否存在、描述是否一致 |
| 概念依赖 | 「高级用法」依赖「快速入门」中的基础概念 | 评估时需确认前置概念是否已在前序文件中定义 |
| 术语一致性 | 多个文件使用同一术语但定义不同 | 需跨文件检查术语定义是否统一 |
| 顺序教程 | Part 1 → Part 2 → Part 3 | 需检查步骤衔接是否连贯、无跳跃 |

**流式处理流程（含跨文件关联）：**

1. **先发现、不读取**：用 Glob 扫描所有文件路径，建立文件清单（路径 + 预估大小），不读取内容

2. **轻量预扫描 — 建立关联索引**：在正式评估前，快速读取每个文件的**元数据层**（仅标题、`##` 章节名、`[链接](目标)` 形式的交叉引用、文件开头 200 字摘要），不读取正文。据此构建：
   - **交叉引用映射表**：记录「源文件 → 链接目标文件」关系，标记哪些目标文件存在、哪些缺失（疑似死链）
   - **依赖排序**：根据引用关系推断阅读顺序，将基础文件（被引用多、不引用他人的）排在前面，依赖文件排在后面
   - **术语索引**：提取各文件中出现的核心术语（大写缩写、反引号包裹的技术名词），标记首次出现的文件

3. **维护跨文件上下文**：流式处理过程中，始终保留一份轻量上下文（不包含原文，仅结构化数据）：
   - 已处理文件的标题、摘要、核心术语列表
   - 交叉引用映射表（实时更新链接验证状态）
   - 术语首次定义位置和定义内容

4. **按依赖顺序逐文件流水线**：按步骤 2 的依赖排序依次处理每个文件：
   - 读取文件内容（大文件分段读取后拼接）
   - 内容预处理（提取标题、章节、代码块、摘要、图片、链接）
   - 文件分类（归入 API 参考 / 教程 / 概念 / README / 故障排查 / 其他）
   - 三维度评估，**额外增加跨文件检查项**：
     - 本文件引用的其他文件是否存在？（对照交叉引用映射表）
     - 本文件使用的术语是否与前序文件定义一致？
     - 本文件是否重复定义了前序文件已定义的概念？
     - 若为系列教程的一部分，与前序文件的步骤衔接是否连贯？
   - **释放该文件原文**，将评估结果和更新后的术语/引用信息追加到跨文件上下文中

5. **PDF 优先处理**：若存在 PDF 文件，优先处理 PDF，再逐文件处理 MD

6. **结果累积**：每处理完一个文件，将评估结果追加到累积结果集中（仅保留分数、证据、问题列表等结构化数据，不保留原文）

7. **汇总时补充跨文件问题**：阶段三汇总时，基于完整的交叉引用映射表，额外输出：
   - 死链清单（引用了不存在的文件）
   - 术语不一致清单（同一术语在不同文件中定义冲突）
   - 内容重复清单（多个文件重复介绍同一概念）

**模式选择规则：**
- 文件总数 ≤ 10 且预估总行数 ≤ 10000 → **普通模式**（一次性全部读入，跨文件关联自然可见）
- 文件总数 > 10 或预估总行数 > 10000 → **流式处理模式**（含跨文件关联感知）

#### 4. 内容预处理

对每个文件读取后的内容做预处理：
- **提取标题**：MD 文件取第一个 `# ` 标题；PDF 文件取前 200 字符中最可能的标题行
- **识别章节**：MD 文件按 `#`/`##`/`###` 标题分割；PDF 文件按空行 + 大写开头行或编号行分割
- **提取代码块**：MD 文件提取 ` ``` ` 围栏代码块；PDF 文件按等宽字体或缩进块识别
- **生成摘要**：取每个文件/章节的前 300 字符作为内容摘要
- **编目图片**：汇总每个文件中提取到的所有图片，生成图片清单（含编号、alt 文本/标题、源路径、所在章节、尺寸信息），统计每文件图片数量
- **编目超链接**：汇总每个文件中提取到的所有超链接，生成链接清单（含编号、链接文本、目标 URL、所在章节、内部/外部链接标记），统计每文件链接数量，标记疑似失效链接（如 URL 格式异常、指向不存在的锚点等）
- **图片与链接关联**：记录图片和链接与所在章节的对应关系，供后续 SubAgent 按章节评估时使用

#### 5. 控制范围与记录

- 读取发现的所有文档文件，不设上限
- 每文件记录：标题、文件路径、文件类型（MD/PDF）、章节数、内容摘要
- 读取失败时记录原因，继续处理其余文件
- **单文档检测**：若最终有效文件数为 1，标记为「单文档深度评估模式」，阶段二各 SubAgent 自动启用深度评估

### 阶段二：文件分类与 SubAgent 分发

#### 1. 文件分类

读取完成后，主 Agent 先对所有文件/章节做类型归类。根据文件路径、标题、内容特征，将每个文件（或大文件中的每个章节）归入以下类型之一：

| 类型 | 识别特征 | 示例文件/路径模式 |
|------|----------|-------------------|
| API 参考 | 函数/接口/类/方法签名、参数表、返回值说明 | `api/`, `reference/`, `classes/`, `*api*.md` |
| 教程/指南 | 步骤式结构（"第一步…第二步…"）、操作指令 | `guide/`, `tutorial/`, `quickstart/`, `getting-started` |
| 概念/概述 | 大段说明文字、架构图、无代码或极少代码 | `overview/`, `concepts/`, `intro/`, `architecture` |
| README | 文件名含 "README" 或为目录首页 | `README.md`, `index.md` |
| 故障排查 | 错误码、常见问题、排查步骤 | `troubleshoot/`, `faq/`, `errors/`, `FAQ` |
| 其他 | 无法归入以上类型 | — |

分类结果写入一张映射表，供后续 SubAgent 使用。

#### 2. SubAgent 分发（3 个并行）

启动 **3 个 SubAgent 并行**评估，每个负责一个维度。各 SubAgent 互不依赖，完全并行执行。

**关键改进：按文件类型分批输入。** 每个 SubAgent 收到的不是全部文件，而是按类型分组后的文件列表，并附带该类型对应的评估侧重说明（来自 `references/standard.md` 的「不同文档类型的评估侧重」表）。这样 SubAgent 可以针对不同类型调整评估重点，同时减少单次上下文负担。

**SubAgent 分配与输入：**

| SubAgent | 维度 | 权重 | 接收的文件类型 | 评估侧重 |
|----------|------|------|---------------|----------|
| SubAgent 1 | 完整性 | 33.3% | 全部类型 | API 参考侧重参数/返回值/错误码完整性；教程侧重步骤完整性；README 侧重安装/基本用法完整性 |
| SubAgent 2 | 正确性 | 33.3% | 全部类型 | 所有类型均关注描述准确性、链接有效性、拼写/标点；API 参考额外关注参数名一致性 |
| SubAgent 3 | 易理解 | 33.3% | 全部类型 | 概念/概述侧重术语解释和架构清晰度；教程侧重渐进式学习路径 |

**每个 SubAgent 的输入包：**
- 按类型分组的文件列表（标题、文件路径、文件类型、正文摘要），**仅包含与其维度相关的类型**
- `references/standard.md` 中对应维度的评分标准（含等级判定条件和子项要求）
- 文档类型评估侧重表（告知不同类型应侧重哪些子项）

**每个 SubAgent 的职责：**
1. 阅读 `references/standard.md` 中自己负责维度的评分标准
2. 对分配给自己的文件逐文件评分（0-10 分），对照五等级判定条件
3. 根据文件类型调整评估侧重
4. 每个分数必须附上具体证据（引用实际文件内容），而非笼统描述
5. 返回结构化结果：维度名称、每文件分数及证据、维度平均分、等级、优点列表、问题列表

**单文档深度评估模式：**

当待评估文档仅 1 个文件时，自动启用深度评估模式。此模式下：

- **按章节逐段评估**：将文档按 `#`/`##`/`###` 标题拆分为章节，每个章节独立评估并记录问题，而非仅给整个文件一个总分
- **逐项对照子项**：对 `references/standard.md` 中本维度的每个评估子项（如完整性 1.1~1.8），逐项检查并记录通过/不通过/部分通过，不通过的必须输出具体问题
- **问题不设上限**：每个章节、每个子项发现的问题全部输出，不限制数量，不合并同类问题
- **代码块逐个检查**：文档中每个 ` ``` ` 围栏代码块单独检查语法、完整性、注释、输入输出
- **链接逐个验证**：文档中每个链接检查有效性和描述准确性
- **术语逐个核对**：文档中每个专业术语检查首次出现时是否有定义或解释
- **输出格式不变**：仍使用标准 SubAgent 输出格式，但问题列表显著更长、更细粒度

**SubAgent 输出格式：**
```
## 维度：[维度名称]（权重 [X]%）

**平均分：** [X.X] — [等级]

| 文件标题 | 文件路径 | 类型 | 分数 | 证据/说明 |
|----------|----------|------|------|-----------|
| [标题] | [路径] | [类型] | [X.X] / N/A | [具体证据] |

**优点：**
- [具体优点，附文件引用]

**问题：**
- [具体问题，附文件引用]
```

**重要提醒：**
- 3 个 SubAgent 完全并行启动，互不依赖
- 主 Agent 等待所有 SubAgent 完成后进入阶段三汇总
- 若某 SubAgent 失败，主 Agent 接管该维度评估作为兜底

### 阶段三：汇总与报告生成

1. **收集 SubAgent 结果** — 等待全部 3 个 SubAgent 完成，收集各维度的评分结果
2. **计算汇总分数** — 每维度取所有已评估文件的**平均分**（N/A 文件排除在外）；完整性、正确性、易理解按权重计算加权总分
3. **合并优点/问题** — 汇总各 SubAgent 返回的优点列表和问题列表。问题列表保留全部条目、不做去重，按「文件路径 → 维度 → 章节」排序后完整列出；优点列表去重后按维度归类。在报告中生成独立的「完整问题列表」区域（表格形式，含编号、维度、文件、章节/位置、问题描述、问题等级六列）
4. **生成报告** — 默认使用 `templates/report.html` 模板生成 HTML 报告；若用户要求 Markdown 格式，改用 `templates/report.md`

### 阶段四：输出

1. 向用户展示完整报告
2. 保存报告到 `./doc-eval-report-[YYYY-MM-DD].html`（Markdown 则为 `.md`；或用户指定路径）

## 评估要点

- **证据要具体。** "`CreateSession` 接口的参数列表缺少类型信息"远比"参数不够详细"有价值
- **聚焦可观察内容。** 无法运行实际系统时，评估文档自身的内部一致性、信息完整度、结构质量
- **不要对无法验证的内容过度扣分。** 代码示例无法运行验证时，关注其完整性和结构
- **全量评估。** 读取到的所有文件均参与评估，不做采样丢弃
- **追踪读取进度。** 维护已发现/已读取/已跳过文件列表，写入报告附录
- **单文档深度评估。** 仅 1 个文档时，按章节粒度逐段评估，每个评估子项逐项对照，问题全部输出不设上限，代码块/链接/术语逐个检查

## 相关文件

- `references/standard.md` — 完整的评分标准（含各等级描述和不同文档类型的处理策略）。评估前务必阅读。
- `templates/report.md` — 可选 Markdown 格式报告模板
- `templates/report.html` — **默认** HTML 格式报告模板（含内联 CSS 样式、等级颜色编码、进度条）
