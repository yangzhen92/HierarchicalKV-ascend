# 1. 概述

## 1.1 简介

本RFC的核心目标是利用Ascend 950PR&950DT 系列产品架构以及带宽优势，实现HierarchicalKV-ascend（下称HKV）的性能优化，解决HKV中的SIMT算子在NPU上带宽利用率低的问题，通过提升数据搬运效率进而提升HKV的整体性能。

## 1.2 动机

在推荐系统的动态Embedding场景中，HKV需要高频执行大规模key-value的插入、查找、更新等操作，value的搬运对HBM带宽利用率有极高要求。Ascend 950PR&950DT 系列产品支持SIMD和SIMT两种算子模式：SIMD算子通过MTE指令能高效利用带宽，但不支持离散、随机数据处理；SIMT算子弥补了这一缺陷，能够处理离散和随机数据访问，但受限于线程数、寄存器数等架构约束，无法打满带宽，导致HKV核心算子（如insert_or_assign、find等）的带宽利用率偏低，直接影响端到端训练和推理吞吐。

当前痛点：HKV的SIMT算子在处理大规模Embedding表时，带宽利用率仅为SIMD模式的50%，成为系统性能瓶颈。

本提案提出一种在SIMT算子中"下发"MTE指令的混合范式，由SIMT作为生产者、UB作为任务队列、Scalar指令作为消费者，形成生产-消费模式，充分利用MTE指令的高带宽优势。该方案可将SIMT算子的带宽利用率提升至SIMD模式的90%以上，显著提升HKV整体性能，提升产品竞争力。

## 1.3 目标

**目标：**
1. 设计并实现SIMT+MTE混合算子范式，通过SIMT生产数据搬运任务、Scalar消费并下发MTE指令的生产-消费模式，提升SIMT算子的带宽利用率。
2. 将HKV核心算子（insert_or_assign、find等）的带宽利用率提升至SIMD模式的90%以上，使核心算子在value>=256B时，平均性能提升30%。

**非目标：**
1. 仅涉及纯HBM模式下的性能优化，不考虑DDR以及HBM+DDR模式。
2. 仅在value>=256B时应用此优化方案；value<256B时，MTE指令带宽利用率与SIMT模式差距不大，无法显著提升性能。
3. 仅对涉及value搬运的接口（如insert_or_assign、find、export_batch等）应用此优化方案，其他接口（如find*、assign_scores等）由于不涉及value搬运，不受到影响。

# 2. 用例分析

**用例1：insert_or_assign（批量插入或更新）**
- 功能点：向哈希表中插入新的key-value-score元组。若key已存在，则更新其value和score；若key不存在且桶未满，则插入新条目；若桶已满，则按淘汰策略覆盖最低分key（除非新key的分数更低）。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例2：find（批量查找）**
- 功能点：搜索哈希表中指定的keys，返回对应的values和命中状态。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例3：insert_and_evict（插入并淘汰）**
- 功能点：向哈希表插入key-value-score元组。若key已存在则更新；若桶已满，最低分key将被覆盖，被淘汰的key-value-score分别输出到evicted_keys/evicted_values/evicted_scores，并输出淘汰计数。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例4：find_or_insert（查找或插入）**
- 功能点：搜索哈希表中指定的keys，当key缺失时将对应的value和score插入表中。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例5：assign（批量更新）**
- 功能点：为已存在的keys分配新的value、scores。若key不存在，则忽略该key的操作。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例6：assign_values（批量更新value）**
- 功能点：为已存在的keys分配新的values。若key不存在，则忽略该key的操作。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例7：find(miss)（查找并收集未命中key）**
- 功能点：搜索哈希表中指定的keys，当key未命中时，将未命中的keys、values收集输出，并输出未命中数量。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**用例8：export_batch（批量导出）**
- 功能点：从哈希表中导出指定数量的key-value-score元组，从指定offset位置开始，输出成功导出的计数。
- 关键性能指标：纯HBM模式下，value>=256B场景性能提升20%；全部接口平均性能提升30%。
- DFX要求：保证接口兼容，仅做性能优化，无功能变更；全场景模式下，无性能劣化。

**使用限制与约束：**
- 混合范式仅适用于Ascend 950PR&950DT 系列产品及以上芯片。
- 性能指标在纯HBM模式下生效。
- value>=256B场景下单接口性能提升20%，全部接口平均性能提升30%。

# 3. 方案设计

## 3.1 总体方案

**硬件平台：** Ascend 950PR&950DT 系列产品，支持SIMT和SIMD两种算子模式，具备Vector流水线、Scalar流水线和MTE（Memory Transfer Engine）流水线。

**核心设计思路：**

Ascend 950PR&950DT 系列产品支持SIMD和SIMT两种算子。其中，SIMT算子弥补了SIMD算子不能进行离散、随机数据处理的问题，但该架构下，SIMT受限线程数、寄存器数等约束，无法打满带宽。SIMD模式下的MTE指令能高效利用带宽。因此我们提出了一个在SIMT算子中"下发"MTE指令的范式。

该范式是由SIMT作为生产者，UB（Unified Buffer）作为中间的任务队列，Scalar指令作为消费者的生产-消费模式。SIMT运行在Vector流水线上，与Scalar指令并行执行。同时SIMT和Scalar都可以访问UB，因此就形成了SIMT生产数据搬运任务，将任务数据填充UB，Scalar循环读取UB数据，下发MTE指令的生产消费模式。该模式极大地提升了SIMT算子的带宽利用率，充分利用Ascend 950PR&950DT 系列产品的带宽优势，提升算子性能。

**核心流程：**

1. **SIMT生产阶段**：SIMT线程（Vector流水线）执行HKV核心逻辑（哈希计算、桶定位、CAS抢占、淘汰决策等），在需要数据搬运时，将搬运任务信息（源地址、目的地址、长度等）写入UB中的任务队列。
2. **Scalar消费阶段**：Scalar流水线与Vector流水线并行执行，循环从UB任务队列中读取任务，通过下发MTE指令完成实际的数据搬运（HBM ↔ UB）。

**限制和约束：**
- UB容量有限，任务队列深度需根据算子的实际数据搬运量进行调优。
- 该范式适用于数据搬运密集型算子（如insert_or_assign、find等），对计算密集型算子收益有限。

## 3.2 技术选型

**方案A：纯SIMT算子极致优化（当前方案）**
- 思路：使用纯SIMT算子，通过warp访存合并、vectorize等手段极致优化带宽。
- 优势：无需引入额外的流水线机制，实现相对简单；在value<256B的场景下表现尚可。
- 劣势：受限于SIMT线程数、寄存器数等约束，无法打满带宽；在value>=256B的大value场景下带宽利用率不足。
- 不选理由：在value>=256B场景下性能无法达到目标指标，需要引入MTE高带宽优势。

**方案B：SIMT→SIMD串行循环方案**
- 思路：通过循环调用SIMT完成逻辑计算并下发SIMD（MTE）搬运任务，串行执行计算和搬运。
- 优势：逻辑简单、编码简单、便于理解，复用现有SIMD搬运能力。
- 劣势：引入循环VF_CALL开销；计算与搬运串行执行，无法实现流水线掩盖，性能无法达到最优。
- 不选理由：无法实现计算与搬运的流水线重叠，性能提升有限，舍弃。

**方案C（本提案）：SIMT+MTE混合范式**
- 思路：SIMT作为生产者将搬运任务写入UB，Scalar作为消费者读取UB并下发MTE指令，两者并行执行形成生产-消费流水线。
- 优势：充分利用SIMT的灵活性和MTE的高带宽；Vector和Scalar流水线并行，实现计算与搬运互相掩盖，隐藏搬运延迟。
- 劣势：引入UB任务队列管理开销；需处理SIMT与Scalar间的同步。
- 选择理由：在保持SIMT算子灵活性的同时，通过MTE指令高效利用带宽，且通过流水线重叠进一步隐藏搬运延迟，性能提升显著。

## 3.3 功能与性能设计

### 3.3.1 UB任务队列设计

```cpp
class MteTaskQueue {
public:
  // SIMT：申请任务元数据空间
  producer_acquire();
  // SIMT：写入搬运任务
  memcpy_async();
  // SIMT：提交任务，使消费者可见
  producer_commit();
  // Scalar：执行任务体
  run_task();
  // SIMT：等待任务完成
  consumer_wait();
  // SIMT：释放任务空间
  consumer_release();
};
```

## 3.4 安全隐私与DFX设计

### 3.4.1 SIM仿真能力

为提升可测试性和可维护性，添加SIM仿真能力，支持通过CPU模拟NPU的架构模式进行仿真和性能分析。

- **仿真架构**：通过CPU多线程模拟NPU的SIMT线程模型，用软件模拟UB、Scalar流水线、MTE指令队列等硬件组件。
- **功能验证**：仿真模式下，HKV算子的执行逻辑与NPU实机完全一致，可在无NPU硬件环境下进行功能正确性验证。
- **性能分析**：仿真模式支持输出指令级执行流程、UB占用率、MTE任务队列深度、Vector/Scalar流水线重叠度等性能分析数据，辅助开发者定位性能瓶颈。

### 3.4.2 日志分级与问题定位

支持通过环境变量设置INFO、WARNING、ERROR等日志级别开关，打印内部流程数据辅助问题定位与分析。

- **环境变量**：通过`HKV_LOG_LEVEL`环境变量控制日志级别，取值为`0`（INFO）、`1`（WARNING）、`2`（ERROR），默认为`2`（ERROR）。
- **日志级别说明**：
  - `INFO`：输出内部流程数据，包括建表、扩容、桶定位、CAS抢占、淘汰决策、MTE任务下发等核心信息，用于问题定位与日常运维监控。
  - `WARNING`：输出异常告警信息等。
  - `ERROR`：仅输出错误信息，用于错误定位。
- **性能保障**：日志关闭情况下，不引入额外开销。
- **输出通道**：日志通过标准错误输出（stderr），支持重定向到文件，便于离线分析。

# 4. 缺点和风险

该方案只有在value>=256B场景下才能发挥出MTE的高带宽优势。在value<256B场景下，引入同步、任务队列管理等开销，纯SIMT算子更优。
